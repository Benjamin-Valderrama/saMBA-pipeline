## saMBA-pipeline

This repository stores the scripts used to build the **S**outh **A**merican **M**icro**B**iome **A**rchive (saMBA). 

If you use this pipeline to build other archives, please cite our work:
> [The South American MicroBiome Archive (saMBA): Enriching the healthy microbiome concept by evaluating uniqueness and biodiversity of neglected populations](https://www.biorxiv.org/content/10.1101/2025.04.03.647034v1)

## Run a demo of the workflow

To enhance reproducibility and to make its use easier for others, we have created a Docker container with all the software and dependencies required to run the pipeline. **NOTE:** The instructions below assume that [Docker is installed](https://docs.docker.com/engine/install/).

Preparation:
``` {bash}
# pull the image of the container to your local machine
docker pull bvalderrama/samba:v1

# check that docker was pulled correctly
docker image ls
```

You should see something like this:
```
REPOSITORY          TAG       IMAGE ID       CREATED        SIZE
bvalderrama/samba   v1        8956704ac0c8   13 hours ago   4.7GB
```

If correctly pulled, we can start the analysis. Files required to run the demo are shared along with the container. 
Please note that running times may vary depending on the internet connection, as samples have to be downloaded from the INSDC 
before starting the analysis. On a Ubuntu machine with 32 cores the running time ~30 minutes. 

``` {bash}
# run the docker image interactively
docker run -it bvalderrama/samba:v1
```

You should notice the terminal has slightly changed. That means we are within the container. Now, we
do the following:

```{bash}
# enter the folder with the required software
cd saMBA-pipeline

# get instructions of how to use the workflow
bash bin/samba.sh -h

# run the demo
bash bin/samba.sh -i demo/test.tsv -o samba_demo -f -r demo/reduced_silva.fa.gz > build_demo.log &
```

The command above should output a number. That's the process ID. You can check the status of the 
workflow with `ps <process ID>`

Once the demo run is finished, we can check the files generated by the workflow.
```
ls samba_demo
```
You will see some new folders. You are free to explore their content. Below we provide an short overview 
of the folder tree generated when running our demo. In-depth details of the outputs generated by each of the
major modules can be found in their respective pages 
(see [Description of the workflow](https://github.com/Benjamin-Valderrama/saMBA-pipeline/wiki#2-description-of-the-workflow))

```
samba_demo/                             # Output folder provided to samba.sh
|
|-- PRJEB11419/
|    |-- 00.rawdata/                 # Raw data of the project
|    |-- insdc-metadata-run-info.tsv # Metadata in INSDC
|    |-- 01.dada2/                   # DADA2 outputs
|    |-- outputs/                    # ASV.fa and project count table used for consolidation
|    |-- logs/                       # Individual log files for each step in the analysis
|
|-- PRJNA325931/                     # Same structure of PRJEB11419
|-- PRJEB36585/                      # Same structure of PRJEB11419
|-- PRJNA486009/                     # Same structure of PRJEB11419
|
|-- logs/
|    |-- PRJEB11419.logs             # Overview of the analysis progress for the project
|    |-- PRJNA325931.logs            # Same as PRJEB11419.log
|    |-- PRJEB36585.logs             # Same as PRJEB11419.log
|    |-- PRJNA486009.logs            # Same as PRJEB11419.log
|
|-- consolidated/                    # Archive-level consolidated outputs
```

Now, you can make a copy of the files generated to your machine. For simplicity,
we will copy the archive level genus count table.

```{bash}
# first, we need to exit the docker image.
exit

# in your machine, you can identify the ID of the container.
docker ps -a
```

You should see something like:
```
CONTAINER ID   IMAGE                  COMMAND       CREATED             STATUS                     PORTS     NAMES
389ad2acd467   bvalderrama/samba:v1   "/bin/bash"   About an hour ago   Exited (0) 6 seconds ago             youthful_borg
```

We will copy the genus-level count table generated by running the demo on the 27 samples across 4 studies.
To do so, you need to use the container ID shown in your machine. 

```{bash}
# remember to change the ID (389ad2acd467) to what was shown above by your machine
docker cp 389ad2acd467:/saMBA-pipeline/samba_demo/consolidated/genus_count_table.tsv .
```
If successful, you should see a message like:

`Successfully copied 34.3kB to /path/to/folder/.`

While this approach would be enough for the demo, it is not enough to generate full archives with thousands of samples. 
If interested in building your own archive, we recommend to read how to work with
[volumes in Docker](https://docs.docker.com/engine/storage/volumes/). Volumes allow Docker to write the files generated
by the workflow directly to your machine. 

You can also go to the section [Description of the workflow](https://github.com/Benjamin-Valderrama/saMBA-pipeline/wiki#2-description-of-the-workflow) for detailed descriptions of each of the modules deployed in the workflow you have just deployed.
